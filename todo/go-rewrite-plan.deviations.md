# Implementation decisions taken during the Go rewrite (append-only)

- Decided by the build: the `Tool` type (server, name, description, input schema, handler) is defined in `config.go`, not `mcp.go`, because `Config.Tools` needs it and `config.go` is written before `mcp.go`; `mcp.go` uses it as is.
- Decided by the build: the interface behind `Config.Session` is named `SessionResolution` (the Python's own term for the same choice), because the session type itself is `Session`. Its values are `NewSession{ID}`, `ResumeSession{ID, Fork}`, and `ContinueLastSession{Fork}`; since `NewSession` is a type, the session's constructor cannot be a function named `NewSession` (the plan's `Start` is free). Pointer values of the three types are refused by `Config.Validate`.
- Decided by the build: `go.mod` lists strictcli, go-toml/v2, go-runewidth, and x/term as direct requirements (strictcli for `internal/cli`, go-toml/v2 for the `agent` package, x/term for the printer's terminal check behind `--color`, go-runewidth for display-width column alignment in the printer's tables), and uax29/v2, smm-h/go-toml-edit, and x/sys as indirect. `github.com/stricttools/go-toml-edit` is not required: nothing in the module graph requires it (strictcli v0.38.0 imports only `github.com/smm-h/go-toml-edit`), and santhosh-tekuri/jsonschema is not listed because strictcli imports it only from tests. `go.sum` also carries the x/text v0.14.0 and dlclark/regexp2 v1.11.0 lines copied from strictcli v0.38.0's own `go.sum`, because strictcli's requirements put them in the module graph.
- Decided by the build: `experiments/go.mod` declares `module experiments`, as the plan states, rather than rlsbl scaffold's `scratch.invalid/rlsbl-scratch`; `experiments/.gitignore` holds `*`, `!.gitignore`, and `!go.mod`.
- Decided by the build: `SystemInit.PermissionMode` is read from the wire key `permissionMode`, the spelling Claude Code 2.1.220 sends (measured in `tests/fixtures/transcripts/simple_send.jsonl`); the Python read `permission_mode`, which never arrives.
- Decided by the build: `SystemInit.MCPServers` is a list of `{name, status}` objects (`MCPServerStatus`), the shape Claude Code sends for MCP servers; the Python declared a list of strings. A frame in any other shape becomes an `UndecodableEvent`.
- Decided by the build: the authentication check reads the assistant frame's top-level `error` field (measured: `"error": "authentication_failed"` in `tests/fixtures/transcripts/simple_send.jsonl`), not `message.error` as the Python did (never present), and matches case-insensitively on `authentication_failed` in addition to the plan's "not logged in", "invalid authentication", and "401"; with only the plan's three substrings the check would never fire on the measured frame. The parser exposes the field as `parsedLine.assistantError` and the check as `isAuthenticationError`.
- Decided by the build: both rate-limit shapes (`system`/`rate_limit` fields and the `rate_limit_info` object of `rate_limit`/`rate_limit_event`) accept `resets_at`/`resetsAt` and `rate_limit_type`/`rateLimitType`, the snake_case spelling winning when both are present. The Python accepted both spellings only in the system shape.
- Decided by the build: `--disallowedTools` is never emitted and has no `Config` field: no Python config field ever set it. The other process fields no config ever set (`--bare`, `--remote-control`, `--remote-control-session-name-prefix`, `--worktree`, `--disable-slash-commands`, `--chrome`, `--ide`, `--tmux`) are not ported either.
- Decided by the build: `Debug.Filter` set with `Debug.Enabled` false is refused by `Config.Validate`; the Python silently turned debug output on. `Debug.File` alone stays allowed and passes `--debug-file`.
- Decided by the build: `Config.Validate` reports every problem at once (joined, each wrapping `ErrInvalidConfig`) and also refuses empty entries in list fields, a comma inside a `BuiltinTools` entry (the flag takes one comma-joined value), empty or `=`-containing `Env` keys, a `JSONSchema` that is not a JSON object, non-positive `Limits` fields, and tools without a server, name, input schema, or handler, or declared twice.
- Decided by the build: `ToolResult.ToolName` is a string, empty when no matching `ToolUse` was seen; `FileWrite.ContentLength` counts Unicode code points, as Python's `len` did. `ToolResult.ContentText` renders a string as itself and an array block by block (text blocks as their text, other blocks as their JSON, joined by newlines).
- Decided by the build: a user frame whose content is a plain string yields no events, as do its non-`tool_result` blocks and blank stdout lines; unknown assistant content blocks (for example `redacted_thinking`) yield `UnknownContentBlock`.
- Decided by the build: the sandbox's realpath follows symlinks through the longest existing prefix and appends the missing rest, matching Python's non-strict `os.path.realpath`; any resolution error other than "does not exist" (permission denied, a file used as a directory, a symlink loop) denies the request with the error in the message, where Python's realpath ignored it. A `file_path` that is not a string is denied.
- Decided by the build: a `control_request` with no `request_id` at either level cannot be answered and becomes an `UndecodableEvent`; a `control_response` whose subtype is anything other than `success` resolves its request with a `*ControlError`.
- Decided by the build: budget and totals live in `budget.go` as `sessionTotals` (cost and tokens set from each `Result`, turns counted) and `budgetTracker.check(header, totals)`, which stamps the given header on each `BudgetThreshold`.
- Decided by the build: the `agent` package reads `format_version` in a lenient first pass before the strict decode, so a file of another format version is refused for its version (naming 2) rather than for keys this version does not know.
- Decided by the build: in an agent file, `[sandbox]` requires `skip_permissions` (security posture, no implicit default), `[mcp]` requires both `config_files` and `strict` (both were required in the Python's `McpOptions`), and every `[[tools]]` entry requires `server`, `name`, and `input_schema` (the root `Tool` needs all three; the Python's optional `server` produced a tool on a server named None). Tool names are unique within a definition, because handlers are matched by tool name. `model`, when present, must not be empty. `[budget]` lists stay optional.
- Decided by the build: `agent.LoadByName` and `agent.List` require a non-empty cwd; `List` treats a missing agents directory as holding no agents, skips entries that end in neither `.agent.toml` nor `.agent.json`, and fails on any `.agent.json` file (pointing at the documented migration) as well as on any bad `.agent.toml`, reporting every bad file at once. `LoadByName` refuses names that are empty, `.`, `..`, or contain a path separator, and its not-found error lists the agent names the directory holds.
- Decided by the build: `agent.ResolvePrompt` keeps the Python's placeholder rule (`{name}`, name of Unicode letters, digits, and underscores, matching Python's `\w`; no escape, so `{{name}}` resolves to `{value}`) but substitutes in one pass over the template, so a value containing `{other}` is never substituted again; the Python's sequential `str.replace` made that depend on dict order. Unresolved placeholders and unused variables are reported together.
- Decided by the build: `agent.BuildConfig` refuses a base config that sets `SystemPrompt`, `SessionName`, or `Tools` (the definition sets them, and the Python silently dropped the base's values); handlers are an `agent.Handler` alias of the root `Tool.Handler` function type. `BuildConfig` does not validate the result; `claudestream.Start` does.
- Decided by the build: `launch.go` exports `ResolveOnPath(name)` (with the `ClaudeProgram` and `ClaudewheelProgram` names) for the CLIs to fill in the binary paths; an absent program wraps `ErrNotOnPath`, and a program found only through a relative PATH entry is refused (Go's `exec.ErrDot`). It also exports `CheckClaudeVersion(ctx, claudeBinary, timeout)` and `CheckProfileVersion(ctx, claudewheelBinary, claudeBinary, profile, timeout)` for `doctor`, both wrapping `ErrVersionCheck`, with `MinimumClaudeVersion = "2.0.0"`; a version below the minimum is returned together with its error. `ProfileExecArgv` builds the `claudewheel profile exec --name P -- ...` prefix for both `buildArgv` and `doctor`.
- Decided by the build: the subprocess's three standard streams are `os.Pipe` pairs, not `exec.Cmd`'s pipe helpers, so the process can be reaped while stdout is still being drained (the helpers close the read end on `Wait`, which can lose the last lines) and so stdin writes honor deadlines; a stdin pipe without deadline support refuses the start. `Config.Env` keys replace the process environment's entries and are appended in sorted order.
- Decided by the build: kept stderr lines are trimmed, blank ones skipped, invalid UTF-8 replaced, and each capped at 64 KiB with a ` [line truncated by claudestream]` marker; a stderr read error other than EOF or a closed pipe is kept as a final line.
- Decided by the build: Claude Code 2.1.220 answers `initialize` and `mcp_set_servers` with control responses carrying no `request_id` (measured in `tests/fixtures/transcripts/mcp_handshake.jsonl`), so a response without an ID resolves whichever of the two handshake requests is waiting; Start sends them one at a time, and with none or both waiting such a response is an `UnknownEvent`. Every other control response is matched by its ID.
- Decided by the build: a stdin write takes the write lock through a channel so the wait ends with the context, and the write itself ends with the context through a past write deadline. A write that stopped part-way leaves a broken frame, so it marks the session unusable and every later write is refused with `ErrSessionUnusable`.
- Decided by the build: the reader queues an event for every request it cannot answer normally: an undecodable `can_use_tool`, `request_user_dialog`, or `mcp_message` is answered with a control error response and queued as `UndecodableEvent`; an `mcp_message` for an unknown server or method is answered with the JSON-RPC error and also queued as `UnknownControlRequest`; a failed write of any automatic answer is queued as an error the turn's `Next` returns (Claude Code waits for that answer, so the turn cannot end), which makes the session unusable.
- Decided by the build: the authentication check runs on every assistant frame, not only the first (the plan's "the first assistant message whose error contains"); the frame's events are queued before the `ErrAuthentication` error so the message Claude Code wrote stays visible. Each turn-ending error (`ErrAuthentication`, the process's exit error, a failed automatic answer, the context's error) makes the session unusable; after the process exited, a send returns its exit error rather than `ErrSessionUnusable`.
- Decided by the build: the turn's end is queued after a `Result` (and its `BudgetThreshold` events) only while a turn is open and its end has not been queued yet; a `Result` arriving with no open turn is delivered at the start of the next turn like any other event. `LastResult` is reset by each send, as the Python did.
- Decided by the build: `SDKToolCall` is queued before the tool's answer is written, so it always precedes the turn's `Result` (Claude Code can send the `Result` only after it has the answer); the `events.go` doc comment says so. A handler error answers `{"content":[{"type":"text","text":<error message>}],"isError":true}`; `tools/call` without params or with undecodable params is -32602. A notification (`notifications/initialized`) is answered with ID 0, as the Python did and Claude Code accepted in the recorded handshake.
- Decided by the build: the session records the IDs of the `PermissionRequest` and `UserDialogRequest` events it queued; `RespondAllow` and `RespondDeny` accept only an unanswered permission request ID, `RespondDialog` and `RespondDialogCancelled` only an unanswered dialog ID, and anything else wraps the new `ErrUnknownRequest`. A failed write leaves the request unanswered so it can be answered again. `RespondDeny` takes its message explicitly (the Python defaulted to "Denied by user").
- Decided by the build: operations after `Close` return the new `ErrSessionClosed`. `Close` waits up to the shutdown timeout for the reader to drain stdout before closing the output pipes (a descendant holding them open cannot keep it waiting), and up to the shutdown timeout for tool handlers to return after their context ended; a handler still running then is reported in `Close`'s error.
- Decided by the build: `GetContextUsage` returns `ContextUsage{TotalTokens, MaxTokens, Percentage, Categories []ContextCategory{Name, Tokens}, AutoCompactEnabled, Raw}`, defined in `control.go`; `Interrupt` returns an empty slice when `still_queued` is absent.
- Decided by the build: every strictcli option the plan names exists at v0.38.0 (`WithEffect`, `WithDryRunUnsupported`, `WithInteractive`, `OwnsStdout`, `MemberChoiceFlag`/`MemberChoice`, `Repeatable`, `ctx.Payload`, `ctx.Document`, `ctx.Done`, `ctx.JSON`), so nothing is substituted. `WithInteractive` is not used: no command in the plan's table reads a terminal interactively.
- Decided by the build: strictcli v0.38.0's `Context` has no stdout writer for unterminated text outside `OwnsStdout` (`ctx.Out` ends every call with a newline) and no unprefixed stderr writer (`ctx.Warn` and `ctx.Error` add `warning: ` and `error: `), so the session commands write live text and markers to `os.Stdout` and `os.Stderr` directly outside machine mode, as dirstat does; strictcli's framework-use lint reports these as stdout-write and stderr-write findings. In machine mode (`--json`), text meant for stdout in `ask`, `stream`, `send`, and `agent run` goes through `ctx.Out` one complete line at a time into the document's output member (the framework guards the process stdout there); `events` owns stdout and writes the raw lines through `ctx.Document()`. Errors go through `ctx.Error` (uncolored, `error: ` prefixed, a diagnostic in machine mode).
- Decided by the build: `NO_COLOR` is declared with `strictcli.WithHandshakeEnv` and read with `ctx.InfraValue` (the lint refuses `os.Getenv`). Color is decided per stream: `--color` forces it on and `--no-color` off; with neither, stdout and stderr are each colored when they are a terminal and `NO_COLOR` is unset or empty. Under `--json` the guarded stdout is not a terminal, so it is uncolored unless `--color` is passed.
- Decided by the build: `--color`, `--footer`, and every other optional session flag declare `Optional()` (strictcli refuses `Default` on mutating commands); with neither `--footer` nor `--no-footer` the footer is written, the Python's fallback, and the help says so. `events --json` never writes the footer, because its stderr carries the `--json` document.
- Decided by the build: `--skip-permissions` sets `Config.Sandbox` to `&Sandbox{SkipPermissions: true}` (no tool list, no write paths, so no `--permission-prompt-tool stdio`); `--no-skip-permissions` leaves `Sandbox` nil, as the Python's `_build_config` did.
- Decided by the build: the selectors are `prompt-source` (`--prompt <text>` or `--prompt-from-stdin`), `session` (`--new-session`, `--resume <id>`, or `--continue-session`), and, on `agent run`, `agent info`, and `agent validate`, `agent-definition` (`--agent-name` or `--agent-file`); the selector names appear only as kwargs keys and in help and errors. No fork option is exposed. An empty value for any string flag is refused, as is a whitespace-only `--prompt`; `--prompt-from-stdin` trims surrounding whitespace and refuses an empty prompt (as the Python did), and standard input is read only after every other flag checked out. `--claude-binary` and `--claudewheel-binary` must be absolute paths; without them `ResolveOnPath` finds the programs.
- Decided by the build: a `PermissionRequest` or `UserDialogRequest` ends the turn with an error and exit 1 once its marker is rendered: the command line cannot answer either, and Claude Code would wait for the answer forever. Neither should arrive, because the command line never sets `InterceptPermissions`, `SupportedDialogs`, tools, or a restricting sandbox (an agent's `[sandbox]` with tools or write paths answers its requests itself).
- Decided by the build: the printer applies miniclaude's "streamed since the last block" rule to text only. Thinking is not streamed: `send` writes each finished top-level `Thinking` block dimmed on stdout as `[thinking: ...]` (the Python's rendering) and `stream` writes `[thinking...]` to stderr. Subagent text and thinking (`ParentToolUseID` set) are not rendered, as in miniclaude; subagent tool calls are, marked `(subagent of <id>)`. The printer ends an open stdout line before a block line and at the turn's end, instead of the Python's unconditional newline after the `Result`.
- Decided by the build: the printer writes stderr markers for `PermissionDecided`, `UserDialogRequest`, `SDKToolCall`, `UnknownControlRequest`, `NonJSONLine`, and `UndecodableEvent`, which the Python had no rendering for, marks error tool results (`--- Result (error) ---` in `send`, `[result: error]` in `stream`), and shows nothing for `SystemInit`, `CompactBoundary`, `FileWrite`, `FileEdit`, `UnknownEvent`, and `UnknownContentBlock`; an event type it does not know is an error.
- Decided by the build: `ask`'s `AskResult` payload has the Python `AskResult`'s fields plus `session_id` (from the `Result`, so a caller can `--resume` it); `text` concatenates the turn's top-level `AssistantText` blocks (the Python also concatenated subagent text); `cost_usd` is `Result.TotalCostUSD`. The schema lists every field as required and refuses others; `usage` and `api_error_status` may be null. The payload is supplied in both modes; the text is printed with `ctx.Out` only outside machine mode, and only when the turn did not end in an error. `ask` takes `--footer` like the other session commands.
- Decided by the build: `agent run` has no `--system-prompt` (the definition's resolved template is the system prompt, and `agent.BuildConfig` refuses a base that sets one). Its `--cwd` is both the session's working directory and where `--agent-name` is looked up (the current directory when omitted). A definition with a `[sandbox]` table replaces the command line's sandbox, so `--skip-permissions` or `--no-skip-permissions` must match its `skip_permissions`, or the run is refused naming the flag to pass. The run goes through `agent.Invoke` with no handlers and renders as `stream` does. Duplicate `--var` keys, a `--var` without `=`, and an empty key are refused.
- Decided by the build: `agent list` keeps the Python's optional `--cwd`; `agent info` and `agent validate` look `--agent-name` up under the current directory. `agent validate` prints `Valid: <name>, version <version> (<path>)`; `agent info` prints name, version, file, description, model, placeholders, tools, and whichever of the sandbox, budget, MCP, and stream tables the file has.
- Decided by the build: `doctor` also takes optional `--claude-binary` and `--claudewheel-binary`, so it checks the binaries a session given the same flags would use. `claude -v` runs within `DefaultVersionCheckTimeout`, the same bound a session start uses; the profile check runs within 10 seconds, because it starts claudewheel before claude. Each check prints one `[ok]` or `[FAIL]` line through `ctx.Out`; the profile check is reported as failed, not run, when either path did not resolve.
- Decided by the build: every failure exits 1. An error after an interrupt (the handler's context ends on the first SIGINT or SIGTERM) is reported as `interrupted: ...`. An error from `Session.Close` is reported and makes the exit code 1.
- Decided by the build (review): `startProcess` no longer discards pipe `Close` errors or the waiter's `cmd.Wait` error. Close failures on the start-up error paths are joined into the returned error; a failure to close the parent's copies of the child's pipe ends after a successful start kills and reaps the process and refuses the start, because a child end left open would keep stdout's EOF from ever arriving. A wait failure other than a non-zero exit (`*exec.ExitError`) is kept on the process and joined to the `*ErrProcessExited` the reader reports at EOF.
